# High-Level Design: Hybrid Relationship Engine

* **Version:** 1.5
* **Scope:** RPG Character Interaction System
* **Architecture:** Hybrid (LLM Classifier + Deterministic Processing Engine)

---

## 1. Executive Summary

This document outlines the architecture for a procedural relationship engine. Unlike pure LLM approaches (which can hallucinate or fluctuate wildly), this system uses a **"Witness/Judge"** pattern.

* **The Witness (LLM):** Strictly classifies narrative input into structured data.
* **The Judge (Deterministic Code):** Calculates the mathematical impact of that data on character relationships based on defined personality matrices.

This ensures that character behavior remains consistent, numerically balanced, and strictly adheres to defined personality profiles (e.g., OCEAN models).

---

## 2. Core Concepts (The Building Blocks)

Before detailing the architecture, we must define the atomic units that drive the system. The engine functions by converting these narrative concepts into mathematical values.

### 2.1 Traits (The Input Atoms)

A **Trait** is the smallest unit of recognizable behavior or "social flavor."

* **Definition:** An objective tag assigned to an action (e.g., "Lying" = Dishonesty).

### 2.2 Relationship Axes (The Output Containers)

Relationships are not defined by a single 0-100 bar. An **Axis** is a specific, independent dimension of interpersonal dynamics.

* **Definition:** A named container for "relationship points" (e.g., Respect, Closeness, Attraction).
* **Role:** These are the mutable stats that change over time. A character can have High Respect for a rival but Low Closeness.

### 2.3 Routing (The Topology)

Routing defines the rigid pathways between inputs and outputs.

* **Definition:** The rule that says which Axis a Trait feeds into.
* **Role:** It ensures logical consistency. *Competence* always feeds *Respect*, never *SexualAttraction*. *Kindness* feeds *Closeness*.

### 2.4 OCEAN & Sensitivity (The Modifier)

The **OCEAN** model (Openness, Conscientiousness, Extraversion, Agreeableness, Neuroticism) determines a character's "Sensitivity."

* **Role:** OCEAN acts as a multiplier. It determines how much a Trait matters. A High-Conscientiousness character is hypersensitive to Laziness (amplifying impact), whereas a Low-Conscientiousness character might ignore it.

### 2.5 Polarity (The Intrinsic Bias)

Polarity defines whether a character inherently "Likes" or "Dislikes" a specific Trait.

* **Role:** It sets the direction (Positive/Negative) of the change. A Thief might have a **Positive Polarity** for Dishonesty, while a Paladin has a **Negative Polarity** for the same Trait.

## 3. Architecture Overview

The data flow is unidirectional, consisting of three distinct phases:

1. **Perception (LLM Layer):** The user/world generates text. The LLM maps this text to a predefined Ontology of Traits.
2. **Processing (Engine Layer):** Code calculates the NetImpact using specific Character Logic (Polarity + OCEAN Sensitivity).
3. **Persistence (State Layer):** The relationship state (Axes) is updated and saved.

### Pipeline Visualization

```text
[Input Interaction] 
       ⬇
[LLM CLASSIFIER] -> (Outputs: InteractionDeed JSON)
       ⬇
[DETERMINISTIC ENGINE]
    ├── 1. Polarity Check (Likes/Dislikes)
    ├── 2. Sensitivity Check (OCEAN Modifiers)
    ├── 3. Dimension Routing (Trait -> Axis Map)
    └── 4. Acclimatization (History Check)
       ⬇
[STATE UPDATE] -> (Modifies: Relationship Values)

```

## 4. Data Models & Schemas

The data architecture is structured into four distinct layers that bridge the gap between static configuration and dynamic runtime state.

* **The Ontology (The Rules):** The immutable "physics" of the social world.
* **The Character Profile (The Filter):** The specific configuration of a person (Personality + Preferences).
* **The Interaction Deed (The Trigger):** A transient packet of data generated by the Witness (LLM).
* **The Runtime State (The Memory):** The mutable record of the relationship.

### 4.1 The Ontology (Static Configuration)

This section defines the "Physics" of the social engine—character-agnostic models.

#### 4.1.1 The Vocabulary

The hard-coded lists constraining the system. The LLM may only select from `TraitTag`.

```csharp
// The vocabulary of behaviors the engine understands
Enum TraitTag {
    // Competence
    Ambition, Intelligence, Creativity, Competence,
    Laziness, Indecisiveness, Incompetence,

    // Social/Moral
    Confidence, Charisma, Kindness, Aggression,
    Dishonesty, Pessimism, Formality, Flirtation
}

// The separate axes tracking the relationship dynamic
Enum RelationshipAxis {
    Respect,           // Professional admiration
    Closeness,         // Personal intimacy/Friendship
    Engagement,        // Frequency/Intensity of interaction
    SexualAttraction   // Physical/Romantic tension
}

```

#### 4.1.2 The Sensitivity Matrix (Model Relations)

This static table defines how OCEAN stats modify the impact of specific deeds.
**Logic:** `Character.OCEAN_Value * Multiplier = Impact_Modifier`

| Character High In... | Sensitive To (Traits) | Impact Multiplier | Rationale |
| --- | --- | --- | --- |
| **Conscientiousness** | Laziness, Indecisiveness | -1.5x | High C hates inefficiency. |
| **Conscientiousness** | Ambition, Competence | 1.1x | High C respects drive. |
| **Openness** | Creativity, Pessimism | 1.3x | High O values novelty. |
| **Neuroticism** | Aggression, Conflict | -2.0x | High N reacts poorly to stress. |
| **Agreeableness** | Kindness | 1.2x | High A values harmony. |
| **Agreeableness** | Aggression, Rudeness | -1.5x | High A dislikes discord. |

    }

This maps Traits to the specific Relationship Axis they affect.

| Trait Cluster | Primary Target Axis | Secondary Target (Optional) |

## 5. Processing Logic (The Engine)

### 5.1 Logic Summary

The change in a relationship axis () is calculated by summing the impact of all perceived traits, weighted by character sensitivity and routing rules, and finally dampened by repetition history.

**Where:**

*  **(Acclimatization):** Penalty factor (e.g., ) if the deed is a recent repeat.
*  **(Magnitude):** Strength of the trait as detected by the LLM ().
*  **(Polarity):** Base character preference ( for Like,  for Dislike,  Neutral).
*  **(Sensitivity):** Multiplier derived from OCEAN stats (e.g., High Neuroticism ).
*  **(Routing Weight):** How strongly this trait maps to this specific axis (from Routing Table).

### 5.2 Algorithm Implementation

This function runs every time the LLM returns an `InteractionDeed`.

```javascript
Function CalculateRelationshipImpact(Deed, Character, RelationshipState) {

    // 1. Initialize Impact Accumulators
    ImpactDelta = { Respect: 0, Closeness: 0, Attraction: 0, Engagement: 0 }

    // 2. Iterate through every trait identified by the LLM
    For Each (Trait, Magnitude) in Deed.PerceivedTraits {

        // --- STEP A: POLARITY (Likes/Dislikes) ---
        // Does the character inherently like this?
        BasePolarity = 0
        If Character.Preferences.Likes.Contains(Trait):
            BasePolarity = 1.0
        Else If Character.Preferences.Dislikes.Contains(Trait):
            BasePolarity = -1.0
        Else:
            BasePolarity = 0.1 // Slight impact for neutral observed traits

        // --- STEP B: SENSITIVITY (OCEAN Filtering) ---
        // Apply multipliers from Sensitivity Matrix (See Section 3.1.2)
        // Logic: OCEAN Value * Rule Multiplier
        Multiplier = 1.0
        For Each (OceanType, Rule) in SensitivityMatrix:
            If Rule.Matches(Trait):
                // Example: High N (0.9) * Negative Multiplier (-2.0) = Very Bad Reaction
                Multiplier = Multiplier + (Character.Personality[OceanType] * Rule.MultiplierValue)

        // --- STEP C: CALCULATION ---
        RawImpact = Magnitude * BasePolarity * Multiplier

        // --- STEP D: ROUTING ---
        // Distribute RawImpact to the correct Stat Bar using Routing Table (See Section 3.1.3)
        // The Routing Table returns a LIST of targets for this trait
        Targets = RoutingTable.GetTargets(Trait) 
        
        For Each Target in Targets:
            // Apply specific weight for this route (e.g., Ambition -> Engagement is only 0.2x)
            RouteImpact = RawImpact * Target.ImpactModifier
            ImpactDelta[Target.Axis] += RouteImpact
    }

    // --- STEP E: ACCLIMATIZATION (Diminishing Returns) ---
    // Prevent spamming the same trick. Check history.
    For Each Axis in ImpactDelta:
         RepeatCount = RelationshipState.History.CountRecent(Axis)
         If RepeatCount > 3:
             ImpactDelta[Axis] = ImpactDelta[Axis] * 0.5 // 50% penalty for repetition

    // 3. Final Commit
    RelationshipState.Metrics += ImpactDelta
    RelationshipState.Metrics.Clamp(0, 100) // Ensure values stay in bounds
}

```

## 6. Glossary of Terms

* **Acclimatization:** A dampening mechanic that reduces the impact of specific actions if they are repeated frequently in a short timeframe, preventing players from "farming" relationships with repetitive loops.
* **InteractionDeed:** The structured JSON output from the LLM (Witness) representing a single game event. It contains the detected TraitTags and their magnitudes.
* **Judge:** The deterministic code component of the engine. It takes the InteractionDeed and applies mathematical rules (Sensitivity, Routing) to update the game state.
* **OCEAN:** The "Big Five" personality model used to define character personalities: Openness, Conscientiousness, Extraversion, Agreeableness, and Neuroticism.
* **Ontology:** The complete set of hard-coded rules and definitions (Vocabulary, Sensitivity Matrix, Routing Table) that govern how the relationship simulation functions.
* **Polarity:** The fundamental reaction a character has to a trait based on their Preferences. (Positive = Like, Negative = Dislike, Neutral = Indifferent).
* **Relationship Axis:** A distinct dimension of the relationship (e.g., Respect, Closeness) that is tracked independently on a 0-100 scale.
* **Routing Table:** A configuration map that directs specific Traits (e.g., "Ambition") to their corresponding Relationship Axis (e.g., "Respect").
* **Sensitivity Matrix:** A set of rules defining how a character's OCEAN values act as multipliers for specific traits (e.g., High Conscientiousness amplifies the negative impact of Laziness).
* **TraitTag:** A specific keyword (e.g., "Kindness", "Aggression") from the controlled vocabulary that the LLM assigns to user actions.
* **Witness:** The LLM component acting as a classifier. Its sole job is to observe the narrative and output an InteractionDeed without making game logic decisions.
